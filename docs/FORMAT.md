# Формат потока Nokia lcbin

Описание получено обратной разработкой трасс нескольких eNodeB и проверено независимыми способами (статистика,
побитовый перебор раскладок, предметные проверки 3GPP, сравнение с декодером pycrate). Все примеры ниже — синтетические
(PLMN 001-01, eNB 12345, сота 7); реальные идентификаторы сетей не приводятся.

## 1. Контейнер

Поток — последовательность записей без промежутков:

| Маркер | Длина | Записи |
|---|---|---|
| `4B 16 B0 55` | u32 BE, **без** 8-байтного заголовка | `60`, `50`, `2E`, `3C`, `48` |
| `0A 0B 0C 0D` | u32 BE, **включая** заголовок | `18` |

Первый байт payload — тип записи. Файлы `neXXXX_….lcbin_<bytes>` с одним префиксом — снимки одного растущего
TCP-потока (меньший является байтовым префиксом большего).

## 2. Числа: varint

Тег `T`: старшие 2 бита = число байт − 1 (1..4), младшие 6 бит входят в значение:
`value = ((T & 0x3F) << 8n) | следующие n байт`. Кодер выбирает минимальную длину.

| Пример | Значение |
|---|---|
| `C0 65 53 F1 00` | 0x6553F100 = 1700000000 — Unix-время |
| `80 01 E2 40` | 123456 — микросекунды |
| `40 12 34` | 0x1234 |
| `00 57` | 0x57 |
| `01 21` | 0x121 (младшие биты тега — часть числа) |

## 3. Идентификаторы (S1AP aligned PER)

- PLMN: 3 байта BCD (TS 24.008), `00 F1 10` → 001-01.
- Global eNB ID (7 байт): PLMN + `00` + 20 бит eNB ID, выровнено влево: `00 03 03 90` → 0x03039 = 12345.
- ECGI (7 байт): PLMN + 28 бит ECI влево; ECI = eNB<<8 | cell: `03 03 90 70` → eNB 12345, сота 7.
- Trace Reference (6 байт): PLMN + 24-бит Trace ID, один на соту. Trace Recording Session Reference (2 байта) растёт на 1 с каждым UE (TS 32.422).

## 4. Типы записей

| Тип | Раскладка |
|---|---|
| `60` заголовок | `60 GlobalENB(7) version(6)` |
| `50` heartbeat ~20 с | `50 GlobalENB(7, младший полубайт C) sec(u32) varint usec` |
| `2E` старт трассировки UE | `2E recordSeq(2) const(2) GlobalENB(7) TraceRef(6) SessRef(2) ECGI(7) varint 0 varint sec varint usec` |
| `3C` конец трассировки UE | то же, но varint = число сообщений в сессии |
| `48` события UE | `48 recordSeq(2) const(2) GlobalENB(7) TraceRef(6) ECGI(7) count(1) элементы…` |
| `18` статус | короткий 24 байта; длинный (байт 14 = 0x11) — см. ниже |

### Элемент записи `48`

```
bitmap(1) ue_id(2) const(1) 16 ue_ctr(2) varint sec varint usec C-RNTI(2) под-поля…
```

| bitmap | Под-поля |
|---|---|
| `7E`/`7F` (бит 0x10) | сначала `varint eNB-UE-S1AP-ID  varint MME-UE-S1AP-ID  TAI(5: PLMN+TAC)  attr(1: 28/30/38)` |
| любой | `00 00 7B len <RRC UL-DCCH UPER>` — MeasurementReport |
| любой | `61 00 <varint TA>` — абсолютный Timing Advance |

TA приходит отдельным элементом сразу после MeasurementReport того же UE с той же меткой времени (ue_ctr+1).
Единица TA = 16·Ts = 0.52 мкс туда-обратно → 78.125 м в одну сторону. Наблюдаемый диапазон укладывается в 11-битный
TA из RAR (0..1282) и выходит за пределы 6-битной команды TA (0..63), т.е. это абсолютное значение. Отдельного
сообщения RAR (преамбула, UL grant, TC-RNTI) в потоке нет. Источник — фича Nokia LTE459 (TA в vendor-specific extension cell trace).

Проверки гипотезы «это TA»: значение стабильно внутри сессии (≈¾ отчётов без изменений, 97 % в пределах ±1, тогда
как RSRP тех же UE гуляет на 5–15 дБ), корреляция с RSRP отрицательная, при новом C-RNTI сбрасывается в 0
и восстанавливается через ~0.1 с, перебор всех битовых окон даёт то же число.

### Длинная запись `18` — UEInformationResponse

```
@0  18 01 0F 0D 00  PLMN(3)  eNB(u32)  00 00  11  00  recordSeq(2)  const(2)  00 00 00 00
@24 TraceRef(6)  @30 u32 0  @34 u32 len  @38 sec(u32)  @42 usec(u32)  @46 SessRef(2)
@48 01 84 04 06 01 16  @54 ECI(u32)  @58 eNB-UE-S1AP-ID(u32)  @62 C-RNTI(u32)  @66 RRC UL-DCCH (UPER)
```

RRC — `ueInformationResponse-r9` с полями: `rach-Report` (число преамбул, коллизия), `rlf-Report` (сота отказа,
сота переустановления, причина, тип rlf/hof, время), `logMeasReport-r10` (MDT: абсолютная метка BCD, Trace Reference,
записи журнала с относительным временем, обслуживающей сотой, RSRP/RSRQ, соседями LTE/UMTS/GSM и координатами).

## 5. RRC-содержимое (TS 36.331, UPER)

- MeasurementReport: measId, RSRP/RSRQ PCell, соседи EUTRA; расширения: `measResultForECID-r9`,
  `locationInfo-r10` (координаты, скорость, GNSS-время), `measResultServFreqList-r10` (SCell, размер списка 1..5).
- Координаты (TS 36.355 в OCTET STRING): `latSign(1) lat(23) lon(24) [altDir(1) alt(15)] [major(7) minor(7) orient(8) [uncAlt(7)] conf(7)]`.
  Широта = ±lat·90/2²³, долгота = (lon − 2²³)·360/2²⁴ (UPER кодирует INTEGER(−2²³..2²³−1) со сдвигом),
  неопределённость = 10·(1.1^K − 1) м, по высоте = 45·(1.025^K − 1) м.
- Пересчёты (TS 36.133): RSRP дБм = idx − 140; RSRQ дБ = idx/2 − 19.5; UTRA RSCP дБм = idx − 115; EcN0 дБ = idx/2 − 24.5; GERAN RSSI дБм = idx − 110.

## 6. Что не расшифровано

- байт `attr` в сессионном префиксе (0x28/0x30/0x38, постоянен для UE);
- 2-байтовые константы после `recordSeq` (одно значение на eNodeB) и байт после `ue_id` в элементе;
- короткие записи `18` с полем `10 1B` / `30 1B`.

## 7. Типичные артефакты

- Сота с репитером или удалённым RRH: группа UE с одинаковым большим TA при сильном RSRP — задержка оптики, а не расстояние.
- Соседние соты одного eNodeB могут иметь постоянное смещение TA друг относительно друга (видно при хендоверах).
